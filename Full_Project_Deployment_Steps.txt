5. Optional Google Maps Globe Setup
-----------------------------------

This is only needed for the 3D globe companion.

GitHub Secret:

GOOGLE_MAPS_API_KEY

Google Cloud requirements:
- Enable Maps JavaScript API if needed by the globe project.
- Enable Map Tiles API for photorealistic 3D tiles.
- Restrict the key by API.
- Restrict the key by HTTP referrer before public use.
- Create billing budget alert.
- Create usage quota for Map Tiles API.

Keep this variable false until those controls are done:

GLOBE_ENABLED=false

If GLOBE_ENABLED=false:
- Main app deploys normally.
- Globe service will not start on AWS.
- Google Maps key is not required for AWS deploy.

If GLOBE_ENABLED=true:
- The CodeDeploy `ApplicationStart` hook loads the AWS Secrets Manager environment and calls `scripts/setup_globe.sh` on each EC2 instance.
- The script clones or updates `GLOBE_REPO_URL`, applies the tracked `scripts/patch_globe_layout.mjs` and native data-layer patches, installs Node dependencies, writes the globe `.env`, and starts `gods-eye-globe.service` on private port 4174.
- GOOGLE_MAPS_API_KEY becomes required.
- You need an ALB target group and host/path listener rule for port 4174 if you want the globe public.
- Set `GLOBE_VIEW_URL` to the resulting public ALB/domain URL. Do not leave it as `127.0.0.1` when the AWS globe is enabled.
- Google Maps usage can create charges when the globe is opened.


6. AWS VPC Setup
----------------

Create VPC:

Name: gods-eye-vpc
CIDR: 10.0.0.0/16

Create 4 subnets across 2 Availability Zones:

gods-eye-public-1    10.0.1.0/24    AZ-1
gods-eye-public-2    10.0.2.0/24    AZ-2
gods-eye-private-1   10.0.11.0/24   AZ-1
gods-eye-private-2   10.0.12.0/24   AZ-2

Why 4 subnets:
- 2 public subnets allow the ALB to be highly available across two zones.
- 2 private subnets allow app EC2 instances to run privately across two zones.
- Public subnets hold ALB and NAT Gateway.
- Private subnets hold EC2 app instances from the Auto Scaling Group.

22. Pre-Deploy Checklist
------------------------

Before running deployment, confirm:

GitHub:
- Code is pushed to main.
- MONGODB_URI secret exists.
- DEEPSEEK_API_KEY secret exists.
- AWS_ROLE_TO_ASSUME variable is real, not placeholder.
- S3_DEPLOY_BUCKET variable is real and bucket exists.
- CODEDEPLOY_APP_NAME matches AWS CodeDeploy app.
- CODEDEPLOY_DEPLOYMENT_GROUP matches AWS deployment group.
- GLOBE_ENABLED=false unless Google Maps quota/billing and the globe ALB route are ready.
- If GLOBE_ENABLED=true, GLOBE_VIEW_URL is the public ALB/domain URL, not 127.0.0.1.
- If GLOBE_ENABLED=true, the CodeDeploy hook must be allowed to install Node/npm dependencies and create the `gods-eye-globe` systemd service.

AWS:
- VPC exists.
- Public and private subnets exist.
- Internet Gateway exists.
- NAT Gateway exists and is available.
- Private route table sends outbound traffic to NAT Gateway.
- ALB exists and points to target group.
- Target group health check path is /api/health.
- ASG exists and has instances running.
- CodeDeploy agent is running on EC2 instances.
- EC2 role can read S3 deployment artifact.
- EC2 role can read Secrets Manager secret.
- GitHub OIDC role can upload to S3, update Secrets Manager, and create CodeDeploy deployments.
- MongoDB Atlas Network Access includes NAT Gateway Elastic IP.

Google Maps if globe enabled:
- GOOGLE_MAPS_API_KEY exists in GitHub Secrets.
- Key is API restricted.
- Key is referrer restricted for public domain.
- Billing alert is created.
- Usage quota is configured.
- GLOBE_APP_PORT 4174 is allowed from ALB security group.
- Globe target group/listener/subdomain is configured.


23. First Deployment
--------------------

Do not run this until AWS setup above is complete.

Go to:

GitHub repo -> Actions -> GOD EYE AWS ASG CodeDeploy -> Run workflow

Set:

deploy_to_aws=true

Click:

Run workflow

What GitHub Actions does:

1. Checks out the repo.
2. Installs Python dependencies.
3. Compiles backend/main.py.
4. Checks frontend JS syntax.
5. Runs a PDF smoke test.
6. Validates required GitHub variables and secrets.
7. Assumes AWS role using OIDC.
8. Writes app secrets to AWS Secrets Manager.
9. Builds CodeDeploy zip.
10. Uploads zip to S3.
11. Registers the CodeDeploy revision.
12. Creates CodeDeploy deployment.
13. Waits for deployment success.

What CodeDeploy does on EC2:

1. Stops old gods-eye service.
2. Installs required OS dependencies.
3. Reads app secret from AWS Secrets Manager.
4. Writes runtime env to /etc/gods-eye/gods-eye.env.
5. Creates/updates Python virtual environment.
6. Installs Python requirements.
7. Starts gods-eye systemd service on port 4173.
8. If GLOBE_ENABLED=true, clones/installs/starts globe service on port 4174.
9. Runs health checks.
