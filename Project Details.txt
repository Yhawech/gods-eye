Project Title:
Cloud-Native GOD EYE OSINT Intelligence Dashboard with 3D Globe Companion

Project Domain:
Cloud Computing, Web Development, DevOps, OSINT, Data Analytics, AI-assisted Intelligence Reporting, Geospatial Visualization

Brief Project Description / Problem Statement:
GOD EYE is a cloud-native OSINT intelligence dashboard that collects, stores, analyzes, and visualizes open-source global incident data from public feeds. The system tracks geopolitical events, military activity, economic/security developments, earthquakes, fires, storms, floods, weather alerts, aviation activity, and other live intelligence items.

The project solves the problem of scattered open-source incident data by combining multiple live feeds into one searchable and filterable dashboard. It provides map-based event visualization, severity scoring, source health monitoring, trend analysis, source credibility scoring, duplicate event merging, dashboard analytics, AI chatbot assistance, saved intelligence reports, and downloadable styled PDF reports.

The application uses MongoDB Atlas as the central cloud database so reports, events, chats, source history, and intelligence records remain available across deployments. DeepSeek AI is integrated to generate analyst-style summaries, incident briefs, report templates, and chatbot responses from the available OSINT context.

The latest version also adds a local 3D geospatial companion integration based on the open-source God's Eye View project by Bilawal Sidhu. This companion can run beside the main dashboard to provide photorealistic 3D globe context, live aircraft and military ADS-B layers, satellites, vessels, active fires, CCTV/camera context, terrain, and other geospatial overlays. The main GOD EYE app remains the intelligence/reporting system, while the 3D globe companion provides richer spatial awareness.

The project includes a native Shadowbroker-inspired OSINT source pack. Instead of running Shadowbroker as a separate application, selected source ideas are integrated directly into GOD EYE's FastAPI refresh pipeline. This adds more specialist military, geopolitical, regional, investigative, world-news  sources while keeping the existing dashboard, MongoDB storage, report builder, PDF export, and AI chatbot workflow unchanged.

The production deployment is designed for AWS using a secure VPC, public/private subnets, Application Load Balancer, Auto Scaling Group, EC2 private app instances, GitHub Actions CI/CD, AWS CodeDeploy, S3 deployment artifacts, AWS Secrets Manager, CloudWatch monitoring, Route 53 DNS, and HTTPS using AWS Certificate Manager.

Event Analysis Algorithms and Libraries:
- Event type classification uses deterministic rule-based keyword matching with Python's `re` regular-expression library. Provider-specific parsers also use source metadata, including USGS magnitude and tsunami flags, NWS severity/urgency/certainty, GDACS alert levels, and feed-specific categories.
- Severity is calculated with provider-specific heuristic scoring functions in `backend/main.py`, normalized to a 1-100 score, and mapped to low, moderate, high, or critical thresholds. GDELT/news items use category base scores plus priority-keyword and major-event escalators. Natural-hazard feeds use published alert, magnitude, urgency, and certainty signals.
- Duplicate reports use deterministic canonical keys. A URL is normalized by removing common tracking parameters such as `utm_*`, `fbclid`, and `gclid`, then hashed with Python's standard-library `hashlib.sha1`. If no URL exists, the system combines normalized title, area, date, and category and hashes that key. Matching items are merged while source names, source count, duplicate count, the highest severity, and the strongest credibility score are preserved.
- Source credibility is a rule-based provenance score, not proof that an event is true. Official source types start higher, recognized official agencies and domains receive an uplift, GDELT and Google News receive defined baseline scores, and blog/social/unknown markers receive a penalty. Scores map to high, medium, developing, or low labels.
- Analyst priority is a separate ranking score that combines severity, category weights, priority keywords, source type, source credibility, source count, and recency. It orders watchlists and reports without replacing the underlying severity score.
- The implementation uses Python standard-library modules including `re`, `hashlib`, `collections.Counter`, and `datetime`, together with FastAPI/Python data structures. It does not currently use scikit-learn, pandas, NumPy, RapidFuzz, embeddings, or a machine-learning classifier for these decisions.
- DeepSeek is used for analyst summaries, chatbot responses, and report generation. It is not used as the deterministic event classifier, duplicate matcher, severity calculator, or credibility calculator.

3D Globe Companion Integration:
The project can run bilawalsidhu/gods-eye-view as a local or optional AWS companion module. GOD EYE remains on port 4173 and the 3D globe companion runs privately on port 4174. The tracked deployment hook scripts clone the companion on EC2, apply the GOD EYE globe patches, install Node dependencies, write its provider configuration, and create a gods-eye-globe systemd service only when GLOBE_ENABLED=true. The dashboard includes a 3D Globe page that launches the companion and reads GLOBE_VIEW_URL from the application environment. In AWS, the globe service is disabled by default; when enabled, it must be routed through an ALB host/path rule and GLOBE_VIEW_URL must be the resulting public URL, never 127.0.0.1. Google Maps Platform is used only for photorealistic globe/map rendering; DeepSeek remains the AI engine for reports and chatbot analysis. The globe OSINT layers use the keyless GDELT DOC 2.0 public-news endpoint through a same-origin Vite proxy, refresh on a bounded interval, and clearly label regional markers as source attribution rather than confirmed operational coordinates.

Shadowbroker-Inspired Integration:
The GOD EYE backend includes selected Shadowbroker-style OSINT source ideas as a native source pack. The integration adds RSS feeds from BBC World, NPR World, Al Jazeera, Guardian World, The War Zone, Bellingcat, Defense News, The Diplomat, SCMP, Yonhap, Asia Times, France 24, and DW.

PDF Reporting:
ReportLab is used to generate styled PDF intelligence reports. Reports include the selected template, summary, source context, event metrics, priority intelligence, hotspots, credibility notes, duplicate-source findings, and collection gaps where available.

Security Design:
- Application instances run in private subnets
- Only the Application Load Balancer is publicly exposed
- EC2 app port 4173 is accessible only from the ALB security group
- The `/api/health` readiness endpoint returns HTTP 200 only when MongoDB is connected and HTTP 503 when the database is unavailable; the main ALB target group accepts only 200
- MongoDB Atlas is accessed through the NAT Gateway Elastic IP
- API keys and database credentials are not stored in code
- GitHub uses OIDC to assume an AWS IAM role instead of storing AWS access keys
- Production secrets are stored in AWS Secrets Manager
- Google Maps keys must be restricted by API and HTTP referrer before public use
